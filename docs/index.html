What it does

Everything here exists because the alternative was four terminal tabs and a guess.

Survives the app

Every service is a tmux session. Quit Harbor and your dev server keeps serving; open it again and it is adopted, not started twice. An update never touches them.

Ports are measured

You never type a port into Harbor. It walks the pane's process tree and asks lsof what is actually listening — so :3000 on a row means something really is on 3000.

Magic

For what pattern matching cannot see — a monorepo, a PM2 config, a socket server, a cron process — Claude reads the project and proposes its services, naming the file each came from. You tick the ones you want.

The edge strip

A column of project chips on the right edge of the screen, above every app and on every Space. Hover for the services, press play without losing focus in your editor.

Crashes stay readable

A service that exits keeps its output and exit code. If the port was taken, the row names the process holding it and offers to kill it — optionally restarting itself three times first.

⌃⌘H

From anywhere: type a project or service name, Enter starts or stops it. The same list lives in the menu bar, under a buoy that fills in while something is running.

How it works

Three decisions the whole app rests on.

01

One tmux session per service

Named from a stable hash of the project path, so the same folder maps to the same session on every launch. That is how Harbor finds services it did not start in this run instead of starting a second copy of your dev server.

02

One poll answers for everything

Every two seconds: one list-panes for liveness and exit codes, one ps for the process tree, one lsof for the ports. Nothing is drawn again unless the value moved.

03

A port is not an answer

Give a service a health path and the dot turns green only when the URL responds — not when the port opens. While a framework is still booting, yellow is the truth.

# a service, really
tmux -S /tmp/harbor-501.sock new-session -d -s hb-3b92hjqj-5de35ab8 \
  'cd backend && npm run dev'

# what Magic answers, in 20 seconds
backend   npm run dev   dir note-app-backend   health /health
client    npm run dev   dir note-app-client
note  the backend needs MySQL and Redis, migrations via npm run migrate
note  all four Nuxt apps default to port 3000, so they collide if started together

Install

Clone and run one script. It installs tmux with Homebrew if you do not have it.

git clone https://github.com/erenbekman/harbor.git
cd harbor
./install.sh
Add a folderHarbor reads it and offers what it finds — npm, pnpm, yarn, bun, artisan, Django, docker compose.
